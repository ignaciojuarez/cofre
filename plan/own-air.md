# Air ownership plan

The useful rule is: move a complete, testable data or UI concern into a small Swift 6 facade, then delete the ObjC bridge method it made unnecessary. Keep a compatibility seam only while the device path proves the replacement. “One new Swift file” means a real owner can be added in `app/Glue/` without cloning Air internals or adding an upstream patch.

The pinned checkout already has Cofre-owned catalogs, mods, JIT, one-step Forge/NeoForge selection, and the launch UI. The launch UI still delegates download and surface startup to Air, so that is ownership of presentation rather than ownership of the game runtime.

## Hard boundary

Air must keep the JVM launch (`JavaLauncher` and JNI/JLI setup), rendering (`egl_bridge`, GL/Vulkan/SDL and MobileGL), input (`JavaGUIViewController` and the input hooks), and the game surface (`SurfaceViewController`). Those pieces own native thread attachment, renderer ABI and library loading, touch-to-Java event timing, the first-frame handoff, and process-level JVM exit behavior. Replacing them in Swift would be a new engine, not a quick cleanup. Cofre should own the data, progress model, and screens around that boundary.

## Recommended order: three quick wins

1. **DONE — `app/Glue/AirBridge/CofrePreferences.swift` (commit `ac2ae57`).** A typed store now owns Air key mapping, defaults, profile-over-global resolution, round-trips, renderer availability, and Air's automatic RAM ceiling. The ObjC bridge is a profile-aware get/set pair; the old raw profile dictionary is gone. In-memory coverage is in `tests/preferences/CofrePreferencesTests.swift`. Device verification: open Settings, change renderer or JVM arguments, save, relaunch, and confirm the value persists; renderer choices are filtered to dylibs in the app's Frameworks directory.

2. **`app/Glue/AirBridge/CofreLogStore.swift` — log source and crash model.** Implement the existing `LogSource` facade (`logLines(_:)`, `exportLog(_:)`) as an actor that reads the current file, tails appended lines, and maps `latestlog.txt`/crash data to `LogLine`. Keep patch 0004 while the launch coordinator still needs the exit notification. Test line splitting, truncation, cancellation, and export URLs with temporary files. Verify `[Cofre] log stream opened kind=…`, `[Cofre] log line count=…`, and `[Cofre] launch exit code=…` in `Documents/latestlog.txt`; confirm the Cofre crash state appears without `PLCrashView`.

3. **`app/Glue/AirBridge/CofreWorldStore.swift` — worlds and server persistence.** Implement the `LibraryService` worlds/servers methods and `OptionalActions.deleteWorld`/`addServer` through a small path-resolver protocol. Initially preserve Air’s resolver output, then move profile-directory resolution into the store once profile migration tests pass. Unit-test temporary isolated/shared roots, `level.dat` filtering, stable IDs, duplicate server addresses, and delete safety. Verify `[Cofre] worlds profile=… count=…` and `[Cofre] server saved profile=… address=…` on device, then relaunch and confirm both lists survive.

These three reduce bridge traffic and hidden UI without touching the hard Air boundary. After their device markers are stable, take profile storage, then the downloader and account/installer projects in separate, evidence-backed migrations.
